# 资料契约

下列记录为确定性生成的本地合成资料，不含真实主体信息。不同文件通过标识字段关联，版本、生效时间、缺失状态和回执字段保留原始业务含义。

| 文件 | 字段 | 记录数 |
| --- | --- | ---: |
| `daily_metrics.csv` | `store_id`, `date`, `metric`, `value`, `metric_version`, `source_state` | 120 |
| `store_context.csv` | `store_id`, `region`, `format`, `open_minutes`, `renovation_state`, `peer_group` | 24 |
| `events.csv` | `event_id`, `store_id`, `date`, `event_type`, `campaign_id`, `inventory_state`, `source_ref` | 60 |
| `diagnoses.csv` | `diagnosis_id`, `store_id`, `metric`, `period_start`, `period_end`, `metric_version`, `review_state` | 36 |
| `actions.csv` | `action_id`, `diagnosis_id`, `owner`, `action_type`, `accepted_at`, `due_at`, `execution_state`, `outcome_ref` | 48 |

数据缺失、待审、争议和未回执均表示状态未知或处理中，不能解释成零值或成功。记录中的模拟日期用于复现跨期关系，不表示真实业务发生。

## 字段语义

| 字段 | 取值 | 处理方式 |
| --- | --- | --- |
| `source_state` | `complete` / `partial` / `device-out` | `device-out` 是设备缺数，数值置空、不按 0；`partial` 可用但需提示覆盖率 |
| `metric_version` | 如 `MV-0` | 同一指标不同版本不混合计算；历史诊断保留原版本 |
| `review_state` | `draft` / `reviewed` / `reopened` / `rejected` | 只有 `reviewed` 的诊断允许提出行动 |
| `execution_state` | `proposed` / `accepted` / `done` / `late` / `rejected` | `late` 表示**逾期未完成**，不计入已执行；`done` 若缺 `accepted_at` 也不计入 |
| `accepted_at` | 日期或空 | 空表示门店尚未接受承诺；此时 `done`/`late` 只作记录，不计执行 |
| `outcome_ref` | 自由字符串或空 | 指向结果回看记录；`done` 但为空会被标记待补 |
| `inventory_state` | `available` / `low` / `out` | `low`/`out` 视为促销期的库存风险，列作混杂因素 |

导入时不会补造资料中不存在的字段：例如 `actions.csv` 没有完成日期，导入的 `done`
记录保持 `completed_at` 为空，在统计中单列为“完成日期未知”，不当作按时完成。

## 已知的资料问题（导入后会由 `verify` 报告）

- `daily_metrics` 中存在门店属性里没有的 `ST-000`，无法参与同业比较。
- 36 条诊断声明的 `metric_version` 与对应门店该指标的实际版本不一致，
  在同口径下没有可用观测，证据会判为“证据不足”。
- 8 条已标 `done`/`late` 的行动缺少 `accepted_at`，不计入已执行。
